# Критерии оценивания

Максимум 100 баллов. Оценивается состояние репозитория, а не объём текста.

## Часть 1. Починка красного CI — 40 баллов

| Критерий | Баллы | Как проверять |
| -------- | ----- | ------------- |
| Все джобы `part1-ci.yml` зелёные на GitHub | 15 | вкладка Actions |
| `./scripts/check-part1.sh` полностью зелёный локально | 10 | скрипт |
| Тесты не изменены | 10 | `git diff` против исходного коммита |
| Правила не ослаблены | 5 | в `pyproject.toml` нет новых `ignore`, `# noqa`, `# type: ignore` |
| Понятные коммиты | — | не оценивается |

Частые способы потерять баллы:

* «починил» линтер, но уронил тесты — минус за невнимательность к проверкам;
* изменил ожидаемое значение в тесте, чтобы тот стал зелёным;
* удалил тест, который «мешал»;
* поднял `mccabe.max-complexity` или добавил `ignore = ["C901"]`.

## Часть 2. TDD и агент — 45 баллов

| Критерий | Баллы | Как проверять |
| -------- | ----- | ------------- |
| Тестов не меньше 10, в каждом есть `assert` | 5 | `./scripts/check-part2.sh` |
| Все 10 правил валидации и шаги расчёта 1–10 покрыты тестами | 10 | ручная проверка против `specs/checkout.md` |
| Покрытие `shop.checkout` не ниже 90 % | 10 | джоба `checkout-coverage` |
| `calculate_order_total` и `validate_order` верны | 10 | скрытые тесты преподавателя |
| Порядок коммитов: тест раньше кода | 5 | джоба `tdd-history` |
| Агент не правил тесты, код без классов и исключений | 5 | `git log -p` |

**Скрытые тесты преподавателя** — самый полезный инструмент. Держите набор
проверок, который не выдаётся студентам: он ловит «подгонку» под четыре
примера из ТЗ. Достаточно 10–15 кейсов на границах: ровно 10 единиц, ровно
25, ровно 50, ровно `FREE_DELIVERY_FROM_KOPEKS`, промокод `VIP35` вместе
с ярусной скидкой, неподдерживаемый город, пустой `sku`, `qty` с пробелами.

## Качество работы — 15 баллов

| Критерий | Баллы |
| -------- | ----- |
| Понятные сообщения коммитов, логичная история | 5 |
| Код читается без комментариев, имена осмысленные | 5 |
| Работа с агентом осознанная: виден процесс, а не только результат | 5 |

Процесс работы с агентом оценивается по истории: чередование коммитов
«тест → код», небольшие шаги, отсутствие коммита, где тесты и реализация
приехали вместе и разом всё переписали.

## Как принимать работу

1. `./scripts/check.sh` — базовая допусковая проверка.
2. Скрытые тесты преподавателя против `calculate_order_total`.
3. Просмотр `git log --oneline` и одного-двух `git show`.
4. Пять минут разговора: что показал красный CI, что делал агент, где не
   поверил агенту и почему.

## Что не оценивается

* Скорость работы и число коммитов.
* Использованный агент и его версия.
* Оформление документации: дописывать её не требуется, но испорченные
  существующие файлы документации — это потеря баллов за качество.
