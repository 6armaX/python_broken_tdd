# shop-broken-tdd — учебный репозиторий

Лабораторная работа по пяти темам: **форматтеры**, **линтеры**, **типы**,
**CI**, **тестирование с TDD** и **LLM-агенты**.

Репозиторий специально приходит в «красном» состоянии: сборка в CI падает, часть
тестов красная, две функции-заглушки не реализованы. Ваша задача — починить
сборку, а затем реализовать расчёт суммы заказа по TDD, с LLM-агентом в роли
исполнителя.

Используемый стек: **uv** (зависимости и виртуальное окружение), **ruff**
(форматирование и линт), **mypy** (типы), **pytest** (тесты), **GitHub Actions** (CI).

## Быстрый старт (Ubuntu)

```bash
git clone <url-репозитория> && cd shop-broken-tdd
./scripts/setup.sh      # поставит uv, Python 3.12 и зависимости
./scripts/check.sh      # локальная копия всех проверок CI — сразу будет красной
```

Подробная инструкция, включая ручную установку и разбор типовых проблем:
[`docs/00-environment.md`](docs/00-environment.md).

## Устройство CI

Два независимых workflow, каждый со своими джобами:

* `part1-ci.yml` → `format`, `lint`, `types`, `tests` (тесты части 1 на Python 3.12
  и 3.13);
* `part2-ci.yml` → `tests`, `checkout-coverage` (не ниже 90 % покрытия
  `shop.checkout`), `tdd-history` (проверяет, что тесты написаны раньше кода).

Команды CI и команды скриптов **одина в один**: `./scripts/check.sh` запускает все
проверки пайплайна, а `./scripts/check-part1.sh` и `./scripts/check-part2.sh` —
его части. Это главный навык работы: чинить сборку локально по выводу
инструментов, а не в веб-интерфейсе GitHub.

## Правила проекта

В проекте намеренно **нет классов и исключений**: данные — это словари и списки,
некорректный вход возвращается через `None` и ранний `return`. Придерживайтесь
этого стиля и в своём коде, и в промптах для агента — иначе проверки не совпадут
с тем, о чём их читает `docs/01-toolchain.md`.

Правила для LLM-агента вынесены в [`AGENTS.md`](AGENTS.md).
